## 强制门

- [ ] 唯一执行链路：public pipe → ServiceCore → per-profile worker → DiskRuntime → M3 → phdskmnt。
- [ ] `myrd_assert_execution_boundary` 覆盖 `myrd_management` / `myrd_product_ipc` / `myrd_profile` / `myrd_m5_worker_protocol`，并有负例测试。
- [ ] 不新增第二套状态机、JSON IPC、profile 格式或 host 执行核心。
- [ ] 不改变 M3 的 bundle / journal / manifest 布局，也不改变 M4 前台单阶段 checkpoint 行为。
- [ ] `dirty_epoch` 绝不跨会话比较；"是否 dirty"以 worker 报告的 M3 块级 dirty 为准，答不出来即 unclean。
- [ ] 任何任务不得安装 / 替换 / 升级 / 卸载 `phdskmnt`。
- [ ] `disk remove` / `forget` 无法证明 writer lock / 匹配设备 / bundle identity 安全时**拒绝**，保留 registration 与 bundle，绝不伪报成功。
- [ ] worker replacement 不得触发 removal 或 synthetic checkpoint success。
- [ ] 每次变更都由 scheduler 拥有；客户端超时永不取消一个已安全运行的 operation。
- [ ] 单盘故障只清理该盘已验证拥有的资源；强制终止按 profile 粒度，绝不 `TerminateJobObject` 连坐。
- [ ] 中断提交判定路径**只读**：不建 runtime、不持 writer transaction、不改 bundle。
- [ ] 不消费 `ManagedProfileSnapshot` 到任何客户端投影（不得泄漏路径）。
- [ ] 每个增量都在虚拟机上取得验证读数；开发机只执行不涉及真实物理资源（不创建 worker 进程 / AIM 设备 / 卷）的测试。

## 明确的非目标（附理由，见设计 §12）

- 跨服务重启不中断磁盘（worker 生存 + 重挂接）—— G1–G4 无一条需要，成本最大
- 驱动分发 / 安装 —— `THIRD_PARTY.md` 的再分发边界 + README 已记录的决定
- 页面文件支持 —— 需要 boot-start 内核组件
- Direct-IO 呈现模式 —— 由 `phdskmnt` 决定，本项目不改驱动
- 压缩镜像 / 改基准格式 —— 会作废 M3 全部验收
- 快照回滚到更早 generation —— M6 级独立设计
- VSS / 远程管理 / 加密 / 卷扩容 / 混合盘 / 多语言
